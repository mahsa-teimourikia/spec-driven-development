# Northstar framework-selection workshop

Northstar must choose how AI-2310 will move from intent to verified change without letting a framework become the source of enterprise authority.

## Workflow

1. Read every file in [`source/`](source/). Every workflow style must receive the same `CTX-AI-2310@1-training` package.
2. Complete the [`workshop/starter/`](workshop/starter/) capability profile and selection decision.
3. Run `python3 ../lab.py` from the course directory or use the guided notebook.
4. Compare your work with [`reference/`](reference/) only after recording your trade-offs.
5. Inspect [`candidate/`](candidate/) to see why a feature contest, copied policy, self-approving commands, and unbounded tasks fail.

The four variants are synthetic workflow families—not executions of GitHub Spec Kit, OpenSpec, Kiro, BMad, or any other product. The vendor landscape in the chapter is dated and source-backed; the lab isolates portable operating-model semantics.

Expected reference result: `READY_FOR_OWNER_REVIEW`, zero findings, six of six golden conformance scenarios, and 30 of 30 exact labelled mutation cases. “Ready for owner review” is intentionally not an enterprise adoption approval.
